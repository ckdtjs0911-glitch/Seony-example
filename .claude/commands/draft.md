# 초안 작성 (Claude → Codex → Claude)

요청: $ARGUMENTS

먼저 프로젝트 루트의 `Codex_Review.md`를 읽고 이 명령과 함께 적용한다. 이 명령은 원고(텍스트) 작성까지만 맡는다. PPT/PDF 파일 제작으로 이어지면 `Codex_Review.md` 2·3장을 따른다.

## 0. 요청 파악

- 요청이 비어 있으면: 직전 대화에서 쓸 글이 분명하면 바로 진행한다. 분명하지 않으면 무엇을 쓸지 한 번만 묻고, 답을 받으면 이어서 진행한다.
- 목적, 독자, 형식(메일·보고서·공지·발표 원고 등), 분량, 문체를 파악한다.
- 분량·문체·구성처럼 정해지지 않은 형식 요소는 무난한 기본값으로 정하고 진행한다. 문체는 사용자 지정을 먼저 따르고, 의료기기 관련 글에서 지정이 없으면 `Codex_Review.md` 4장의 문체 원칙을 따른다.
- 수신자 실명, 일정, 수치처럼 사용자만 아는 개별 사실은 지어내지 않고 `[입력 필요: 내용]`으로 표시한다.

## 1. 초안 작성 (Claude)

- 초안은 Markdown으로 쓴다. PPT 원고는 슬라이드별로 `제목 / 본문 / 발표자 노트`를 적는다.
- 사용자가 제공했거나 신뢰할 수 있는 출처로 확인한 사실·수치만 쓴다. 확인하지 못한 내용은 `[확인 필요: 이유]`로 표시한다.
- 의료기기 관련 글은 `Codex_Review.md` 4장의 용어·규격 인용 원칙을 적용한다. 설명 순서·그림 규칙은 교육·설명 원고에, 슬라이드 구성 규칙은 PPT 원고에만 적용한다.

## 2. 검토 요청 (Codex)

Agent 도구로 `codex:codex-rescue` 서브에이전트를 호출한다(`run_in_background: false`). 프롬프트에는 다음을 넣는다.

- "검토만 하고 파일을 만들거나 수정하지 말 것"
- 사용자 요청 원문, 사용자가 준 참고 자료·출처와 작성 중 확인한 출처, 0단계에서 정한 기본값
- 초안 전문
- 적용 규칙: `Codex_Review.md` 경로와, 이 글에 적용한 장
- 확인 항목: 사실관계·용어, 논리 흐름, 빠진 내용, 맞춤법·띄어쓰기·문장, 목적과 독자에 맞는 어조, (PPT 원고라면) 슬라이드당 메시지 하나인지
- 각 지적에 이유와 수정 제안을 덧붙이고, 사실관계·용어 지적에는 출처 또는 확인 근거를 제시할 것

## 3. 반영 (Claude)

- 검토 의견을 하나씩 판단해 반영한다. 반영하지 않은 의견은 이유를 남긴다.
- 반영하다가 의미·수치·주장이 바뀌면 바뀐 부분을 Codex에 다시 검토받는다. 변경 전후 문장과 판단에 필요한 주변 문맥을 함께 보낸다.

## 4. 출력

채팅으로 아래 형식에 맞춰 출력한다. 사용자가 요청하면 파일로도 저장한다. 단, Codex를 쓸 수 없을 때는 아래 절을 따른다.

```
## 최종본
(Codex 검토를 반영한 전문)

## 입력·확인 필요
- (사용자가 채우거나 확인할 부분. 없으면 "없음")

## Codex 검토 결과
- 반영: ...
- 반영 안 함: ... (이유)

## 적용한 기본값
- (0단계에서 정한 기본값. 기본값을 정하지 않았으면 이 항목 전체를 생략)
```

## Codex를 쓸 수 없을 때

`Codex_Review.md` 1장의 "Codex를 쓸 수 없을 때"를 따른다. 이 명령에서는 다음을 추가로 지킨다.

- 초안은 프로젝트 루트의 `drafts/YYYYMMDD-주제.md`로 저장한다. 같은 이름의 파일이 있으면 덮어쓰지 않고 이름 끝에 `-2`, `-3`을 붙인다. (`text_review.md`의 첨삭과 달리 새로 쓴 초안은 잃지 않도록 요청 없이도 저장한다.)
- 출력 형식의 `## 최종본`을 `## Codex 검토 전 초안`으로 바꾸고, `## Codex 검토 결과`에는 `미실시: 사유`를 적는다.

같은 절차를 키워드(`초안 작성`, `초안 만들어줘`)로 실행하는 규칙이 `report_draft.md`에 있다. 한쪽을 고치면 다른 쪽도 함께 맞춘다.
